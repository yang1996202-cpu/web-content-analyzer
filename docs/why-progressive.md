# 为什么渐进式阅读更好？

## 核心问题

很多 AI 使用失败，不是因为 AI 完全读不到内容，而是因为用户把任务问得太大：

```text
帮我看完这个项目，然后安装配置好。
```

这句话同时包含了好几个任务：

- 理解项目是什么
- 找安装要求
- 找安装步骤
- 判断当前系统是否满足条件
- 找配置方法
- 处理报错

如果文档很长，一次性处理这些任务很容易漏掉关键条件。

## 渐进式阅读是什么？

渐进式阅读就是先问结构，再问重点，最后问细节。

```text
第一步：这份文档有哪些主要章节？
第二步：哪些章节和我的目标有关？
第三步：只读最相关章节，给出可执行步骤。
第四步：遇到问题时，再读故障排查章节。
```

它不是更慢，通常反而更快，因为它减少了返工。

## 例子：安装开源项目

不稳的问法：

```text
帮我安装 https://github.com/example/project
```

更稳的问法：

```text
请先查看这个项目文档，找出：
1. 安装要求
2. 安装步骤
3. 不同系统的差异
4. 常见报错
先只回答这些位置在哪里，不要展开无关介绍。
```

然后继续：

```text
我用的是 macOS。请只根据 macOS 相关安装说明，给我一步一步操作。
```

## 为什么这更可靠？

| 方式 | 问题 |
|------|------|
| 一次性读全文 | 容易把介绍、功能、示例和真正步骤混在一起 |
| 先问结构 | 先知道哪里重要 |
| 指定章节 | 减少无关信息干扰 |
| 分步验证 | 哪一步错了就修哪一步 |

## Web Content Analyzer 的作用

它负责在最前面提醒你：

```text
这份内容很短，可以直接读。
这份内容中等，最好带目标读。
这份内容很长，应该先问结构再分块。
```

它真正提供的是一种工作流，而不是一个神奇的网页阅读能力。
